# Japaccent. の作り方（セットアップ手順）

プログラミングがわからなくても、**上から順にやれば公開できる**ように書いています。
所要時間の目安は 30〜60 分、お金は **0 円**（無料プランの範囲）です。

---

## 0. まず全体像

このサイトは 2 つのサービスを組み合わせて動きます。

```
 ┌──────────────────────┐        ┌──────────────────────────────┐
 │ GitHub Pages         │        │ Firebase（Googleのサービス）   │
 │ 「画面」を配る場所      │ ←────→ │ ・Googleログイン               │
 │ index.html など       │        │ ・データベース(Firestore)      │
 └──────────────────────┘        │   申請・承認済み辞書・お知らせ  │
                                  │   BAN・ログイン記録             │
                                  └──────────────────────────────┘
```

- **GitHub Pages** … ファイルを置くだけでWebサイトにしてくれる無料サービス。ただし「ログイン」や「データの保存」はできません。
- **Firebase** … ログインとデータ保存を担当。画面（index.html）の中に Firebase の接続情報を書いておくことで、つながります。

---

## 1. 用意するもの

- Googleアカウント（Firebase用。管理者になるアカウントです）
- GitHubアカウント（無料。https://github.com で作れます）
- パソコンのブラウザ（Chrome推奨）

---

## 2. リポジトリに何を置くか

「リポジトリ」＝ GitHub 上の**ファイル置き場（フォルダ）**のことです。
次の **7 つのファイルを、フォルダに入れずそのまま一番上（ルート）** に置きます。

| ファイル | 何のため？ | 置き場所 |
|---|---|---|
| `index.html` | サイト本体（画面もプログラムも全部入り） | ルート |
| `dictionary.json` | 公開辞書のデータ（誰でも見られる・使える） | ルート |
| `firestore.rules` | データベースの「鍵のルール」（後でFirebaseに貼る。置いておくと記録になる） | ルート |
| `README.md` | 利用者向けの説明 | ルート |
| `README-SETUP.md` | この手順書 | ルート |
| `LICENSE` | コードのライセンス（GPL-3.0） | ルート |
| `LICENSE-DATA` | アクセントのデータのライセンス（WTFPL） | ルート |

> ⚠ `index.html` と `dictionary.json` は**必ずルート**に。フォルダの中に入れると動きません。
> （`dictionary.json` が `https://ユーザー名.github.io/リポジトリ名/dictionary.json` で取れる、というのが「みんなが使える」の正体です）

## 3. GitHub に置いて公開する

### 3-1. リポジトリを作る
1. GitHub にログイン → 右上の **＋** → **New repository**
2. **Repository name** に好きな名前（例: `japaccent`）
3. **Public**（公開）を選ぶ
4. **Add a README file** は**チェックしない**
5. **Create repository**

### 3-2. ファイルをアップロードする
1. 作ったリポジトリのページで **uploading an existing file**（または Add file → Upload files）をクリック
2. パソコンの 7 ファイルを**まとめてドラッグ**
3. 下の **Commit changes** を押す

### 3-3. Pages を有効にする
1. リポジトリの **Settings** タブ → 左メニュー **Pages**
2. **Source** は **Deploy from a branch**
3. **Branch** を `main` / `/ (root)` にして **Save**
4. 1〜2 分待って、同じ画面に出る URL を開く
   → `https://ユーザー名.github.io/リポジトリ名/`

この時点で、**ログインなしの機能（アクセント付与・ローカル保存）はもう動きます。** 🎉
ここから先は、ログイン・申請・管理者機能のための Firebase の設定です。

---

## 4. Firebase のプロジェクトを作る

1. https://console.firebase.google.com を開き、Googleアカウントでログイン
2. **プロジェクトを追加**（または「Create a project」）
3. 名前を入れる（例: `japaccent`）→ 続行
4. Google アナリティクスは**オフ**でOK → **プロジェクトを作成**

### 4-1. 「ウェブアプリ」を登録して、接続情報をもらう
1. プロジェクトのトップで **`</>`（ウェブ）** のアイコンをクリック
2. アプリのニックネーム（例: `japaccent-web`）を入れる。「Firebase Hosting も設定」は**チェックしない**
3. **アプリを登録**
4. 画面に `const firebaseConfig = { apiKey: "...", authDomain: "...", ... };` が出ます。
   **この `{ ... }` の中身をコピー**しておく（あとでまた見られます: ⚙ → プロジェクトの設定 → マイアプリ）

> 💡 この `apiKey` は**公開されても大丈夫**です（パスワードではなく「どのプロジェクトか」の名札）。
> 守っているのは、あとで貼る「ルール」です。

### 4-2. 接続情報を index.html に貼る
1. GitHub のリポジトリで `index.html` を開く → 右上の **✏️（鉛筆）** で編集
2. 次の場所（ファイルの上の方、`<script>` の直後あたり）を探す:

```js
const FIREBASE_CONFIG = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  appId: "YOUR_APP_ID"
};
```

3. `YOUR_...` の部分を、さっきコピーした値に書き換える（`"` は消さない）
4. 右上 **Commit changes…** → **Commit changes**
5. 1〜2 分待つ（Pages が更新されます）

---

## 5. Googleログインを使えるようにする

### 5-1. ログイン方法をオンにする
1. Firebase コンソール左メニュー **構築 → Authentication** → **始める**
2. **Sign-in method（ログイン方法）** タブ → **Google** をクリック
3. **有効にする** をオン → サポートメール（自分のメール）を選ぶ → **保存**

### 5-2. 「このサイトからのログインを許可」する（忘れがち！）
1. Authentication → **設定（Settings）** タブ → **承認済みドメイン**
2. **ドメインを追加** → `ユーザー名.github.io`（`https://` や `/リポジトリ名` は**付けない**）
3. 追加

> これを忘れると、ログインのポップアップに `auth/unauthorized-domain` というエラーが出ます。

---

## 6. データベース（Firestore）を作って、ルールを貼る

### 6-1. 作成
1. 左メニュー **構築 → Firestore Database** → **データベースを作成**
2. ロケーションは **asia-northeast1（東京）** がおすすめ（あとで変更できません）
3. **本番環境モード**で開始 → 作成

### 6-2. ルールを貼る（ここが一番大事）
1. Firestore の **ルール** タブを開く
2. 最初から書いてある内容を**全部消して**、リポジトリの `firestore.rules` の中身を**全部コピーして貼る**
3. **公開** を押す

このルールが、次のことを決めています:

| 誰が | できること |
|---|---|
| 誰でも | 承認済み辞書・お知らせを読む |
| ログインした人 | 出典つきで申請する（1分に3件まで）／自分の申請を読む |
| 管理者だけ | 辞書の直接登録・削除、申請の承認、お知らせ投稿、BAN/TO/キック、ログイン記録(IP)の閲覧 |
| 本人 | スパムを検知したとき自分の制限段階が上がる（自分でBANを解除したり弱めたりはできない） |

## 7. 自分を管理者にする

管理者は「**`admins` というコレクションに、自分のUIDと同じ名前のドキュメントがある人**」です。
アプリからは作れず、**Firebase コンソールからだけ**作れるので安全です。

1. 公開したサイトを開いて **Googleログイン**
2. ヘッダーに出る**自分の名前をクリック** → 「UIDをコピーしました」と出ます（長い英数字）
3. Firebase コンソール → **Firestore Database** → **データ** タブ
4. **コレクションを開始** → コレクション ID に `admins` → 次へ
5. **ドキュメント ID** に、**コピーしたUIDを貼る**（「自動ID」は押さない）
6. フィールドは何でもOK（例: フィールド `role` / 文字列 / `owner`）→ **保存**
7. サイトを再読み込み → 名前の横に **★admin** と出れば成功

別の人を管理者にしたいときも、その人のUIDで同じことをします（UIDは本人に名前をクリックしてもらい、コピーして送ってもらう）。

- [ ] サイトが開く／文章を入れるとアクセントが付く
- [ ] Googleログインできる／名前の横に ★admin が出る

- [ ] 別のGoogleアカウント（シークレットウィンドウ）でログイン → 申請 → 管理者側の「申請」に出る → `y` で承認

- [ ] （試しに）別アカウントで 1 分間に 4 回申請する → 1分タイムアウトの画面が出る → 管理者の `m` 画面で「U」解除

うまくいかないとき → 一番下の「困ったとき」へ。

## 9. 日常の運用

### 申請を承認する
1. `r`（または「申請」ボタン）→ `j`/`k` で選ぶ
2. 出典を確認 → **`y` 承認** / **`n` 却下**（却下は理由を聞かれます。申請者の画面に表示されます）

### 管理者が直接直す・消す
- `e` で編集、`d` → `y` で削除。**管理者なら、承認済みのアクセントも `dictionary.json` にあるアクセントも消せます。**
- 消すと全員の辞書から消えます。

### データを `dictionary.json` に固定する（おすすめ・定期的に）
承認済みのデータは Firebase 側にあります。これを GitHub の `dictionary.json` にもまとめておくと、Firebase が止まっても辞書が残り、読み込みも軽くなります。

1. 管理者でログイン → 上の **「公開用JSON」** ボタン → `dictionary.json` がダウンロードされる
2. GitHub のリポジトリのトップで **Add file → Upload files** → ダウンロードした `dictionary.json` を**同じ名前のままドラッグ** → **Commit changes**（同名ファイルは上書きされます）
3. 1〜2分後に反映

> 💡 Firestore の無料枠は「1日5万回読み取り」です。サイトを開くたびに、Firebase にある辞書の件数ぶん読み取りが発生します（500件なら1回の訪問で500回）。
> 辞書が増えてきたら、上の手順で `dictionary.json` に固定してから、Firebase の `entries` を整理すると軽くなります。

### お知らせを出す
`n` → 上のフォームにタイトルと本文 → `Ctrl+Enter`。消すときは一覧で選んで `x`。

### 荒らし対応（`m` = 管理画面）

| キー（Shiftを押しながら） | 動作 |
|---|---|
| `T` | タイムアウト（分を聞かれます） |
| `K` | キック（強制ログアウト・再ログインは可能） |
| `B` | BAN（アカウント単位） |
| `I` | IP BAN（そのアカウントが使った全IPを禁止） |
| `U` | 解除（BAN・タイムアウト・IP BAN をまとめて） |

- 一覧には各アカウントの**最後のIP**と、**同じIPを使った別アカウント**（＝垢変えの疑い）が出ます。
- すでにBANされたIPからログインした人は **⚠BAN済みIPからログイン** と出ます。
- スパム検知は **1分TO → 3分TO → キック → BAN →（IP BANは管理者の承認待ち）**。5回目に ⚠IP BAN要承認 が出るので、確認して `I` を押してください。管理者自身はスパム検知されません。

## 10. 荒らし対策の「できること／できないこと」（正直な説明）

GitHub Pages は**ただのファイル置き場**で、サーバーのプログラムを動かせません。そのため完璧な締め出しはできません。

| 項目 | 実際のところ |
|---|---|
| 申請・辞書への書き込み | **ルールで本当に止まる**（BAN/TO中は書けない。1分3件の上限もルールで強制）。ここは破れません |
| 画像つきのブロック画面 | **画面側（ブラウザ内）の表示**。開発者ツールを使える人は消せます。ただし消しても**書き込みはルールで止まったまま**です |
| 「閲覧自体を不可に」 | ログインしていない人の**閲覧は止められません**（静的サイトの限界）。BAN済みのブラウザには、ログイン前でも画面を出し続けますが、データを消去・シークレットウィンドウで回避できます |
| IPアドレスの収集 | ブラウザが外部サービス（ipify）に聞いた結果を**自己申告で送る**方式です。**偽装できます**。VPNを使われると意味がありません。あくまで「垢変えの手がかり」と考えてください |
| IP BAN | 同じWi-Fi（学校・会社・モバイル回線）の**無関係な人を巻き込む**ことがあります。乱用しないでください |
| 自動のIP BAN | 自己申告のIPで自動BANすると、**他人のIPを勝手にBANさせる悪用**ができてしまうため、**管理者の承認制**にしています |

もっと強くしたい場合は、Firebase の **Cloud Functions**（クレジットカード登録が必要な有料プラン Blaze が前提）でサーバー側にIP判定を持たせる必要があります。**App Check**（reCAPTCHA）を入れるとボット対策になります。

### 個人情報について
IPアドレス・メールアドレスを集めるので、**何を・何のために集め・誰が見るか**を利用者に伝える必要があります。サイト内の「規約」ボタンとREADME.mdにその文面を入れてあります（法的なアドバイスではないので、本格運用するなら専門家に確認してください）。
IPアドレスの取得で ipify.org（失敗時 Cloudflare）に通信している点も、必ず残してください。

## 11. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| サイトが404 | Pages の設定（3-3）を確認。`index.html` がルートにあるか。反映に数分かかります |
| 「Firebase未設定」/ 下に `cloud: 未設定` | `FIREBASE_CONFIG` を書き換えていない（4-2）。コミット後に数分待つ |
| ログインで `auth/unauthorized-domain` | 承認済みドメインに `ユーザー名.github.io` を追加（5-2） |
| ポップアップが出ない | ブラウザのポップアップブロックを許可 |
| 申請すると失敗する（permission-denied） | ルールを貼り忘れ（6-2）／タイムアウト中／出典が空／1分に4件以上 |
| ★admin が出ない | `admins` のドキュメントIDが自分のUIDと**完全一致**しているか（余計な空白や改行に注意）。再読み込み |
| 管理画面でIPが「取得失敗」 | 広告ブロッカーが ipify を止めている可能性。IP取得できないアカウントは手がかりが減ります |
| 辞書が読み込めない | `dictionary.json` がルートにあるか／JSONの書式が壊れていないか（カンマ・括弧） |
| 直したのに変わらない | Pages の反映待ち（〜数分）。ブラウザで `Ctrl+Shift+R` |

## 12. 改造して自分のサイトを作るとき（ライセンス）

- **アクセントのデータ**（`dictionary.json`）は **WTFPL**。コピーも改変も公開も、好きにしてOKです（`LICENSE-DATA`）。
- **コード**（`index.html`）は **GPL-3.0-or-later**。**自由に改造して公開して構いません**。ただし改造版を公開するときは、同じGPLのまま**ソースも公開**し、元の著作表示を残してください（`LICENSE`）。
- 自分のサイトを作るときは、`FIREBASE_CONFIG` を**自分のプロジェクトの値**に変え、管理者も**自分のUID**で作り直してください。
